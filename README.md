# Instagram 媒体批量保存器（油猴脚本）

在 **Instagram 用户主页 / 帖子页**一键批量保存图片与视频的 Tampermonkey 用户脚本（单文件 userscript）。

- 支持**用户主页网格**（自动巡览逐帖采集 / 手动浏览监听采集）与**指定帖子页**（`/p/` `/reel/` `/tv/`）批量抓取
- **JSON 优先**解析页面内嵌结构化数据（`_sharedData` / `__additionalDataLoaded` / `xdt_api__v1__` 等 `<script type="application/json">` 块），一次拿到整帖全量媒体
- 覆盖：单图、**轮播（carousel 全 slide）**、视频帖、**Reels**
- **递归深搜嵌套媒体（v1.1.3）**：逐层遍历帖子 JSON 结构，提取所有层级的图片/视频——包括**嵌套评论 / threaded 回复**（带图或视频的评论）、**富文本区块**（caption/评论的 `blocks`，支持 `inline_style_ranges.media_id` 引用解析）、**被 @提及的媒体**（`edge_mentioned_media`）；评论分页载荷（独立 `media.shortcode` 上下文）也能追拍，不漏深层内容
- **v1.1.4 优化（下载更干净 / 抓得更全）**：
  - **ZIP 只含真实所需媒体（v1.1.18 起不再生成 `meta/` 文件夹）**——图片在 `images/`、小视频在 `videos/`，不再附带任何元数据 JSON
  - **轮播全量修复**：每页 slide 优先取显式 `display_url`/`video_url`，不再因只暴露 `display_url` 而漏采二层图片/视频（个人主页与单帖页通用）
  - **个人主页多图**：网格瓦片内若堆叠多张预览图则全部抓取（而非仅首张）；JSON 通道已捕获该帖轮播时直接标记完成
  - **完整视频**：单帖/Reels 始终优先 `video_versions` 最大档或 `video_url` 全量，不抓缩略图
  - **诊断导出**：设置面板「📤 导出诊断JSON」可本地下载当前页捕获的真实帖子 JSON 与内嵌结构，便于离线精修抓取逻辑；v1.1.5 起额外捕获原始 GraphQL/SSR 载荷（`rawCaptures`），即使识别器暂未认出结构也不会静默漏抓，导出文件即含真实字段供定位
  - **v1.1.6 适配 2026 Polaris/Relay 字段名（根因修复）**：实测当前 Instagram 已弃用旧 GraphQL 命名，改用 `code`（非 `shortcode`）、`taken_at`（非 `taken_at_timestamp`）、`caption.text`（非 `edge_media_to_caption.edges[].node.text`）、`image_versions2.candidates[].url` / `display_uri`（非 `display_url`）、`video_versions[].url` 作为媒体源；并递归穿透 `require/__bbox/result/data` 包装，正确定位 `xdt_api__v1__media__shortcode__web_info`、`xdt_api__v1__profile_timeline.profile_grid_items`、`xdt_api__v1__feed__user_timeline_graphql_connection` 等真实端点。相关网格项（`profile_grid_items[].media`）仅含 `pk` 无 `code`，已自动回退用 `pk` 作 key（需 `hasMedia` 守卫避免误捕获用户节点）。旧字段名保留兼容回退，老接口页面仍可工作
  - **v1.1.7 视频下载修复（BugFix）**：① HEAD 探测返回异常小值（`content-length: 0`/极小值）时不再直接采信，改走 `Range: bytes=0-0` 兜底，用 `Content-Range` 真实总大小判定——杜绝"有效视频被误判为无效跳过"；② `GM_download` 回调携带 `>=400` 状态（403 签名过期/限流）时记**失败**而非误标"已保存"（此前会把 key 写入已保存记忆，下次采集直接跳过、永不重试）；③ 视频下载失败自动重试一次（CDN 瞬态拒绝常见）。实测视频直链 HEAD 返回 6.7MB 且校验 Referer，URL 本身有效
  - **v1.1.8 自动巡览帖子（自动打开 + 自动切下一帖 + 末页停止）**：设置面板开启「自动巡览帖子」后，网格页自动点开首帖 → 详情页等渲染（轮询主媒体/JSON 就绪，超时跳过防卡死）→ 采集 → **多图检测先行**（JSON 未给全量且 DOM 有轮播按钮则点击展开补全全部图片）→ 自动切下一帖（优先点详情页原生"下一帖"按钮，缺失/无效则返回网格继续）→ 翻到末页自动停止并保存。全程 SPA 导航不刷新页面（已采集媒体不丢失）；去重：visited + 已处理短码 + 已保存记录三重过滤，不重复浏览/下载。参数可在面板调（巡览等待渲染 / 巡览帖子上限）。v1.1.9 移除自动滚动仅保留自动巡览；**v1.1.10 修复**：自动巡览开启后**进入帖子才采集**（未点进帖前暂停一切入库），并修复首帖未自动打开的问题；若提示"无可巡览的帖子"说明全部已处理/已保存，清除断点进度即可重新巡览；**v1.1.11 修复**：巡览时**只采当前帖**（详情页相关网格等旁支内容不再混入），文件名账号前缀改为优先取自帖子 JSON 的 owner（不再因 `/p/短码/`、`/reel/短码/` URL 丢失账号名）；**v1.1.12 修复**：巡览模式开启后网格页一律不入库（连页面加载时捕获的主页 feed JSON 也不再提前采集），只有进入帖子详情页才开始入库；**v1.1.14 修复**：① 同一张图多个尺寸档位不再被当成多张重复保存（按归一化基址去重，每张图/视频只保存一次）；② 翻页后新帖 JSON 先于路由检测到达时不再被旧帖过滤误挡（第二帖完整视频可正常保存）；③ DOM 兜底限定在当前帖主媒体区（main article），不再误采详情页"相关帖子"网格的图片
- 保存为 **ZIP 打包**（图片进 ZIP；视频直接下载，避免大文件占内存），文件名 `{用户名}[_{YYYYMMDD}]_{短码}_{序号}.{ext}`（有发布日期时自动带上 YYYYMMDD；图片按响应头 `Last-Modified` 重命名，见下）
- **自动排除快拍/精选（stories/highlights）封面缩略图**，只保存真实帖子媒体
- 内置**自动巡览（v1.1.8）**、请求预算、风控熔断、断点续抓、已保存记忆

## 安装

1. 安装 Tampermonkey 浏览器扩展（Chrome / Edge / Firefox / Safari）。
2. 新建脚本，将 `instagram-image-saver.user.js` 的完整内容粘贴进去并保存；
   或直接通过 `@updateURL` 从 GitHub 安装（`https://raw.githubusercontent.com/Eiranya/Tampermonkey-JS/main/instagram-image-saver.user.js`）。
3. 打开 `https://www.instagram.com/` 并保持**已登录**。页面右下角出现渐变悬浮按钮「开始采集」即安装成功。

## 使用（三种场景）

| 场景 | 操作 |
|---|---|
| **用户主页采集（自动巡览）** | 打开某用户主页 → 设置面板开启「自动巡览帖子」→ 点击右下角「开始采集」→ 脚本自动打开首帖、逐帖采集并自动切下一帖、翻到末页自动停止保存；不开启时手动浏览页面（滚动/点帖）由监听自动记录 |
| **单帖批量** | 打开任一 `/p/短码/`、`/reel/短码/`、`/tv/短码/` 帖子页 → 点击「开始采集」→ 脚本读取内嵌 JSON 抓取该帖全部媒体（轮播多图 / 视频）→ 点击按钮保存 |
| **设置面板调参** | 点击悬浮按钮旁的齿轮 ⚙ → 调整请求预算、并发、巡览参数等 → 实时生效并持久化 |

采集过程中每张已记录的网格瓦片会打上角标；再次点击按钮停止并保存。**中断/刷新后重新打开页面再点「开始采集」，会自动断点续抓**（恢复已处理短码、分页游标，并自动重试上次下载失败的项）。

## 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| 每半小时请求预算 | 80 次 | 媒体抓取/下载请求计数，达到后自动暂停采集并提示，窗口每 30 分钟翻转 |
| 满量自动保存 | 50 帖 | 已采集帖子数达到后自动触发保存（v1.1.20 起已与缓存上限合并为一个功能） |
| 每包数量 | 150 个 | 每个 ZIP 内媒体数上限（避免内存爆炸） |
| 媒体最小体积 | 50 KB | 图片与视频统一阈值：对原始 CDN 文件双重校验（HEAD/Range 预筛 + 下载后实际字节复核），小于该值的媒体视为无效/损坏跳过保存 |
| 轮播点击上限 | 15 次 | JSON 缺失时"下一张"点击展开的最大次数 |
| 巡览等待渲染 | 15 秒 | 自动巡览时进入详情页等待媒体渲染的最长时间，超时跳过该帖 |
| 巡览帖子上限 | 100 篇 | 自动巡览最多浏览的帖子数，达到后自动停止保存 |
| 自动巡览帖子 | 关 | 开启后自动打开帖子 → 采集 → 自动切下一帖 → 末页自动停止保存 |

> 高级参数（**下载并发** / **下载间隔下限** / **下载间隔上限** / **视频打包阈值** / **ZIP 分卷阈值**）在 Debug 模式下显示：点击 Tampermonkey 工具栏图标 → 菜单「🐞 Debug 模式」开启后，设置面板底部出现这五项（默认 1 路 / 400 毫秒 / 5000 毫秒 / 150MB / 1024MB）。
>
> 注：v1.2.1 起下载并发默认改为 **1 路串行**并移入高级参数——串行拉取对 Instagram CDN 更"像人"，显著降低触发风控的概率，代价是打包速度变慢。
>
> 注：v1.2.2 起**每次下载类请求**（体积探测、媒体拉取、大视频单独下载及失败重试）发出前会随机等待一段时间，间隔在「下载间隔下限 / 上限」之间呈**偏态分布**——短间隔为主、长间隔稀少，避免请求集中发送触发风控。

## 反爬与限流设计（油猴版等价策略）

油猴脚本运行在用户**真实登录**的浏览器会话里，UA 由浏览器控制、IP 由网络出口决定，因此以下两项在油猴边界内**技术上不可实现、也不应伪造**：

- ❌ 代理 IP 池切换
- ❌ User-Agent 轮换

伪造 UA / 绕验证码会把用户账号推向封禁，违背工具初衷。本脚本以等价策略替代：

1. **人在回路人速浏览（v1.1.9 起移除自动滚动，改为自动巡览/手动浏览）**：自动巡览按"等渲染 → 采集 → 切下一帖"节奏逐帖推进（渲染等待默认 15s 上限 + 导航间隔 1.2s），不抢速、不切后台；
2. **全随机化时序**：轮播点击间隔、巡览导航间隔、重试延迟全部随机化，避免固定频率被风控识别；v1.3.0 起每次下载请求前还有随机等待（默认 400ms–5s 偏态分布，斜率降到 2：约 15% 间隔 <0.5s、约 32% >2.5s，比 v1.2.2 的"节拍器式"密集簇更自然），且下载顺序随机打乱，避免请求按采集顺序规律排列，进一步打散请求节奏；
3. **请求最小化**：能读内嵌 JSON 就不点击、能读 DOM 就不发请求；下载串行化并设并发上限；
4. **请求预算封顶**：统计每半小时请求数（默认 80），接近阈值自动暂停并提示，宁慢勿封；
5. **命中即停（采集 + 下载全程）**：遇 `429` / Challenge / `Action Blocked` / 登录墙（含页内登录弹窗的 HTML 表单/文案特征检测，URL 未变也会熔断）立即停止采集与下载并醒目提示，**绝不重试硬闯**；
6. **绝不自动过验证码**：检测到 Challenge 即停手，提示用户手动完成验证。

## 断点续抓（不是 HTTP Range）

断点续传 = **断点续抓**：脚本用 `GM_setValue` 持久化 `ResumeState { processedShortcodes, cursor, startedAt, failedItems }`。

- 中断 / 刷新后可继续，不重复采集已处理短码；
- 分页游标（`next_max_id` / `end_cursor`）随浏览/巡览推进并持久化，避免重复加载同一批帖子；
- **下载失败项会记录**，续抓时自动重试。

## 常见问题

| 问题 | 处理 |
|---|---|
| 提示"检测到登录墙" | 请先在 Instagram 登录，或稍后再试；脚本不会硬闯 |
| 提示"请求过于频繁（429）" | 已自动熔断，等一段时间后点击按钮「解除熔断」继续；可调低请求预算 / 放慢巡览节奏（调大"巡览等待渲染"） |
| 提示"验证码/Challenge" | 脚本已自动停止，请手动完成验证后再点「解除熔断」 |
| 提示"Action Blocked" | 停止操作数小时后再试，避免继续触发风控 |
| 轮播只抓到封面图 | 网格页只暴露首张 slide 属正常；在**单帖页**采集或依赖内嵌 JSON 可获得全量。v1.1.4 起轮播 slide 优先读 `display_url`/`video_url`，若仍漏采可在该帖页点「📤 导出诊断JSON」把真实结构发给我精修 |
| 某些帖子漏采 | Instagram 虚拟化滚动会把滚出视口的帖子移出 DOM——这是平台机制；已用短码/内容签名去重键跨轮次累计，配合 JSON 通道最大程度覆盖 |
| 下载时报 `This domain is not a part of the @connect list` | Tampermonkey 白名单拦截了 CDN 下载域，详见下方排障小节 |

### 排障：`This domain is not a part of the @connect list`

**现象**：点击保存时，下载媒体（如 `scontent-hkg1-1.cdninstagram.com` 等 IG CDN 边缘节点）被 Tampermonkey 拦截，提示 `This domain is not a part of the @connect list`，媒体下载失败。

**原因**：
1. Tampermonkey 的 `@connect` 白名单未覆盖目标 CDN 域（旧版本脚本只声明了部分子域）；
2. 首次下载该域时弹窗授权被点击了「拒绝」，该域被写入「未授权连接列表」；
3. 浏览器缓存了旧版本脚本（旧版未内置裸域名条目）。

**修复步骤**：
1. 打开 Tampermonkey 扩展 → 设置 →「安全性」→「未授权连接列表」，删除其中被拒的 IG CDN 域名（`cdninstagram.com` / `fbcdn.net` 等）；
2. 重新安装/更新到最新版脚本（v1.1.3 起已在元数据块内置 `@connect cdninstagram.com` 与 `@connect fbcdn.net` 裸域名条目，裸域名自动覆盖其所有子域，含多级前缀，如 `scontent-*` / `video-*` / `scontent.cdninstagram.com`；并保留 `*.cdninstagram.com` / `*.fbcdn.net` 通配符双保险）；
3. 再次点击保存，弹窗出现时选择「始终允许」；若提示已消失但下载仍失败，检查 Tampermonkey 是否为最新版本（部分旧版对多级子域的通配符匹配不可靠，裸域名条目最稳）。

**脚本内置对策**：v1.1.1 起下载失败若命中该特征（`connect` / `not allowed` / `blocked` / `not part of`），会弹出醒目中文引导提示并在设置面板状态行标注，方便第一时间定位。

## 已知限制与免责声明

- **递归深搜嵌套媒体（v1.1.3）说明**：脚本会对每个帖子节点做整树递归遍历，逐层提取图片/视频。判定规则：① 已知媒体键（`display_url` / `video_url` / `image_versions2.candidates` / `video_versions` / `thumbnail_src` / `og_video_url`）——天然排除头像（`profile_pic_url`）与迷你缩略图；② 评论/回复节点（含 `text`+`created_at` 或 `edge_threaded_comments` / `edge_comment_media`）标记为 `comment` 来源；③ 富文本 `blocks`（含 `inline_style_ranges.media_id` 引用解析、区块自带媒体）标记为 `richtext`；④ `edge_mentioned_media` 标记为 `mentioned`。深层媒体按 URL 去重、并以 `ig:{短码}:x{哈希}` 命名空间入库，与主媒体（`ig:{短码}:{序号}`）互不碰撞。命中快拍/精选黑名单子树（`edge_highlight_reels` / `edge_reel_media` 等）整棵跳过。
- 真机真网行为需用户实测：Instagram 接口/DOM 随时变更，选择器集中在 `SELECTORS` 映射表、JSON 解析按通道降级，改版后可单点修复；
- 匿名会话限额更严（约 200 请求/小时即被标记），**务必登录使用**，并保持人速浏览/巡览节奏；
- 脚本只采集用户可见内容，请遵守 Instagram 服务条款与内容版权，仅用于个人合法用途。

> **v1.3.0 更新（抗风控参数调整）**：
> - **下载间隔下限 `DOWNLOAD_DELAY_MIN_MS` 300ms → 400ms**（配合上限 5000ms，最低等待更不易被判定为脚本突发）。
> - **下载间隔偏斜指数 `DOWNLOAD_DELAY_SKEW` 4 → 2**（内部常量，不进设置面板）：分布从"约 45% 间隔压在 0.3–0.5s 的密集簇"变为"约 15% <0.5s、约 36% <1s、约 32% >2.5s"，拉长间隔、增加偶发长停顿，节奏更贴近真人。
> - **新增：下载顺序随机打乱**：保存时对所有待下载媒体做 Fisher–Yates 随机排序后再逐一下发，避免请求按采集顺序规律排列（另一个明显机器特征）。内部开关 `SHUFFLE_DOWNLOAD_ORDER`（默认 true，置 false 可恢复原始顺序，仅供调试）。
> - 综合效果：相比 v1.2.2，100 次下载平均等待约 193s（原 124s），但亚秒突发（<0.5s）从 45% 降到约 15%，长尾（>2.5s）更厚，整体更抗风控。
