# Tampermonkey-JS — 社交媒体媒体批量保存脚本合集

> 🤖 **AI 制作声明**：本仓库中的**两个脚本（`twitter-image-saver.user.js` 与 `instagram-image-saver.user.js`）均由人工智能（AI）全程辅助设计、编写、调试与迭代完成**。
> 开发过程采用 AI 驱动的工程化流程：需求拆解 → 架构设计 → 代码实现 → 离线单元测试（Node 沙箱注入内部函数做断言）→ 实机日志与诊断数据回流 → 缺陷定位与修复。
> 代码为 AI 生成产物，欢迎通过 Issues 反馈问题（附上控制台日志或导出的诊断 JSON 便于定位）。

油猴（Tampermonkey）脚本合集，用于批量采集并保存社交媒体上的图片与视频，自动打包成 ZIP 下载。

---

## 📦 仓库内容

| 脚本 | 平台 | 当前版本 | 用途 |
|---|---|---|---|
| `twitter-image-saver.user.js` | X / Twitter | v1.4.0 | 用户主页自动滚动采集，图片 + 视频打包 ZIP |
| `instagram-image-saver.user.js` | Instagram | v1.3.0 | 用户主页 / 帖子页采集（支持自动巡览），原图优先，图片 + 视频打包 ZIP |

两个脚本**相互独立**，可同时安装，互不干扰（分别只在各自平台域名生效）。

## 🐦 脚本一：Twitter/X 媒体批量保存器

在 X / Twitter 用户主页一键记录并批量保存图片和视频，自动打包成 ZIP 下载。

### 功能

- **自动滚动采集**：边滚边记录，无需手动翻页
- 图片和视频一起打包，按每包数量自动分片
- **已保存记忆**：保存过的媒体会记下来，下次不再重复
- 无效 / 过小文件自动过滤（图片 / 视频分别设阈值）
- 推文上实时打角标，采集进度一目了然
- **满量自动保存**（默认 200 个媒体），不用盯着
- **空闲自动停止**：设定窗口内数量无增长则自动结束记录并打包
- 可视化设置面板，参数随时改
- **视频日期自动还原**：从视频 ID 的 Snowflake 时间戳还原成 `YYYY-MM-DD`

### 安装

1. 浏览器装好 [Tampermonkey](https://www.tampermonkey.net/)
2. 打开这个地址：

   ```
   https://raw.githubusercontent.com/Eiranya/Tampermonkey-JS/main/twitter-image-saver.user.js
   ```

3. Tampermonkey 会自动识别脚本，点「安装」即可

装过之后，Tampermonkey 会通过 `@updateURL` 自动检查更新。

### 使用

1. 打开任意 X 用户主页
2. 点右下角的「记录媒体」
3. 脚本开始自动滚动并采集，推文上会出现角标
4. 采够了再点一次，自动打包下载（或等待满量 / 空闲超时自动保存）

按钮状态：

| 状态 | 显示 | 说明 |
|---|---|---|
| 空闲 | 图片图标 + 记录媒体 | 点击开始采集 |
| 录制中 | 实心方块 + 已记录 N | 点击停止并打包 |
| 打包/下载 | 下载图标 + 打包中… | 正在处理，请勿关闭页面 |

### 设置

点右下角的**三点按钮**展开面板，改动即时生效并保存：

| 项 | 默认 | 说明 |
|---|---|---|
| 图片最小体积 | 50 KB | 小于此值的图片视为无效，跳过 |
| 视频最小体积 | 20 KB | 小于此值的视频视为损坏，跳过 |
| 满量自动保存 | 200 个 | 记录到这个数量自动触发保存 |
| 每包数量 | 150 个 | 每个 ZIP 打包多少文件 |
| 下载并发 | 3 路 | 同时下载几个文件 |
| 滚动间隔 | 2000 ms | 自动滚动节奏（带随机抖动） |
| 视频日期 | 推文时间优先 | 另一选项「视频ID优先」，见下 |

面板底部显示当前已保存记录条数，可以一键清除（清除后下次会重新记录所有媒体）。

**视频日期的两种口径**：

- **推文时间优先**（默认）：用推文发布时间，和图片的命名口径一致
- **视频ID优先**：用视频自身的上传时间。转发旧视频时，这个日期才是"视频什么时候拍的"

### 文件名规则

```
图片   2026-08-02_214530_01.jpg
视频   video_2026-08-02_01.mp4
```

- 图片：日期 + 精确到秒的时间 + 同条推文内的序号
- 视频：日期 + 同一天内的序号

### 已知限制

- HLS（m3u8）视频需要下载 init 段 + 全部分片后拼接，**这部分没做过充分的实机验证**。如果遇到长视频下下来不能播，可以到 Issues 反馈
- 只在 `x.com` 和 `twitter.com` 生效
- 已保存记录存在 Tampermonkey 里，换浏览器或清理数据会丢失

## 📷 脚本二：Instagram 媒体批量保存器

在 Instagram 用户主页 / 帖子页批量保存图片和视频（打包 ZIP），**原图优先**，支持轮播全量与自动巡览。

### 功能

- **JSON 优先解析**：优先读取页面内嵌数据（`_sharedData` / `__additionalDataLoaded` / `xdt_api__v1__*`）与 API 响应；详情页 JSON 缺失时主动请求补齐
- **原图优先**：同一张图先采到缩略图（640）、后到原图（2048）时自动高清替换（按内容签名归一化）
- **递归深搜嵌套媒体**：逐层遍历帖子 JSON，覆盖嵌套评论 / threaded 回复、富文本区块、被 @ 提及的媒体
- **轮播全量**：每页 slide 取全量，个人主页多图堆叠全部抓取，完整视频优先（`video_versions` 最大档）
- **自动巡览**（可选）：自动打开帖子 → 采集 → 自动切下一帖 → 末页自动停止保存
- **只采当前帖**：旁支内容（主页 feed / 相关网格）严格过滤，不混入无关媒体
- **下载策略**：浏览过程中**不下任何文件**；保存时图片 + 小视频（< 阈值）进 ZIP（`images/` + `videos/`），大视频（≥ 阈值）单独下载
- **ZIP 分卷**：单包超阈值或满 150 个媒体自动分卷（`_part1` / `_part2`…）
- **已保存记忆 + 断点续抓**：保存过的媒体不重复；游标与失败项持久化，下次自动重试
- **风控保护**：每半小时请求预算、风控熔断、保存前预算预判（不足则提前终止采集并保存）
- **抗风控下载节奏（v1.3.0）**：下载间隔默认 400ms–5s 偏态分布（斜率 2，拉长间隔、偶发长停顿更贴近真人）；保存前对所有媒体做 Fisher–Yates 随机排序，弱化请求规律，降低机器特征
- **满量自动保存**：按**帖子数**（默认 50 帖）触发
- **可视化设置面板** + **Debug 模式**（🔧 按钮显示版本号、Debug 开关、导出诊断 JSON）

### 安装

1. 浏览器装好 [Tampermonkey](https://www.tampermonkey.net/)
2. 打开这个地址：

   ```
   https://raw.githubusercontent.com/Eiranya/Tampermonkey-JS/main/instagram-image-saver.user.js
   ```

3. Tampermonkey 会自动识别脚本，点「安装」即可

### 使用

**方式 A：自动巡览（推荐批量）**

1. 打开 Instagram 用户主页
2. 点右下角「开始采集」→ 设置面板开启「自动巡览帖子」
3. 脚本自动打开帖子、采集、切下一帖，末页自动停止并保存

**方式 B：手动逐个帖子**

1. 打开 Instagram 用户主页，点右下角「开始采集」
2. 手动点进想保存的帖子（只采集当前打开的帖子，主页 feed / 相关网格不会混入）
3. 采够了点「停止并保存」

按钮状态：

| 状态 | 显示 | 说明 |
|---|---|---|
| 空闲 | 相机图标 + 开始采集 | 点击开始采集 |
| 采集中 | 实心方块 + 采集中 N | 点击停止并打包 |
| 已满量 | 实心方块 + 已满 N | 达到缓存上限，点击保存 |
| 保存中 | 下载图标 + 保存中… | 正在打包，请勿关闭页面 |

### 设置

点右下角**齿轮按钮**展开面板，改动即时生效并保存：

| 项 | 默认 | 说明 |
|---|---|---|
| 每半小时请求预算 | 80 次 | 媒体抓取/下载请求计数，达到后自动暂停并提示，窗口每半小时翻转 |
| 满量自动保存 | 50 帖 | 已采集**帖子数**达到后自动触发保存 |
| 每包数量 | 150 个 | 每个 ZIP 内媒体数上限 |
| 媒体最小体积 | 50 KB | 图片与视频统一阈值（HEAD/Range 预筛 + 下载后实际字节复核） |
| 轮播点击上限 | 15 次 | JSON 缺失时"下一张"点击展开的最大次数 |
| 巡览等待渲染 | 15 秒 | 自动巡览时等待媒体渲染的最长时间 |
| 巡览帖子上限 | 100 篇 | 自动巡览最多浏览的帖子数 |
| 自动巡览帖子 | 关 | 开启后自动打开帖子 → 采集 → 自动切下一帖 → 末页停止保存 |

**Debug 模式**：点面板标题栏右侧的**调节滑块图标**按钮展开浮动面板，可查看脚本版本号、开启 Debug 模式（开启后即时显示高级参数与「导出诊断JSON」按钮）。

> 高级参数仅在 Debug 模式下显示：**下载并发**（默认 1 路串行）/ **视频打包阈值**（默认 150 MB）/ **ZIP 分卷阈值**（默认 1024 MB）/ **下载间隔下限·上限**（默认 400–5000 毫秒，下载请求随机等待）。

### 文件名规则

```
{用户名}[_{YYYYMMDD}]_{帖子短码}_{序号}.{扩展名}
示例：travelpics_20260820_DbFdq_smnXP_01.jpg
```

- 日期段优先取媒体响应头 `Last-Modified`，拿不到时回退帖子发布时间 `taken_at`
- 序号为该帖内的媒体顺序（01、02…）
- ZIP 内目录：图片 `images/`、小视频 `videos/`

### 已知限制

- 仅 `instagram.com` 生效
- 从主页 feed 直接点开帖子时，IG 可能复用缓存不请求详情数据；脚本会主动请求补齐（若接口被拒则该帖只有 DOM 兜底）
- 大视频（≥ 阈值）单独下载，不进 ZIP
- 已保存记录与断点进度存在 Tampermonkey 里，换浏览器或清理数据会丢失

## 🔍 两个脚本的核心区别

| 维度 | Twitter/X 脚本 | Instagram 脚本 |
|---|---|---|
| 生效域名 | `x.com` / `twitter.com` | `instagram.com` |
| 采集方式 | 主页**自动滚动**流式采集 | 主页网格 + **自动巡览**逐帖 / 手动点帖 |
| 数据来源 | GraphQL JSON（Timeline）+ DOM | 内嵌 JSON（`xdt_api__v1__*` / web_info）+ API 响应 + DOM 兜底 |
| 采集范围 | 时间线上出现的所有推文 | **只采当前打开的帖子**（旁支严格过滤） |
| 下载时机 | 停止记录后统一打包 | 浏览时不下任何文件，保存时统一打包 |
| 原图策略 | 从 `variants` / 媒体候选取最大档 | JSON 最高清 + **高清替换**（同图 640 → 2048） |
| 去重依据 | URL 归一化基址 | **`ig_cache_key`（内容签名）归一化** |
| 视频处理 | mp4 + HLS(m3u8) 解析后合并 | mp4 直链；< 阈值进 ZIP `videos/`，≥ 阈值单独下载 |
| 文件命名 | `2026-08-02_214530_01.jpg` / `video_2026-08-02_01.mp4` | `用户名_日期_短码_序号.jpg` |
| 日期来源 | 推文时间 或 视频 Snowflake ID | 响应头 Last-Modified 或 帖子 `taken_at` |
| 满量触发 | 媒体数（200 个） | **帖子数**（50 帖） |
| 断点续抓 | 不支持 | 支持（游标 + 失败重试持久化） |
| 风控保护 | 基础（最小体积过滤） | 请求预算 + 风控熔断 + 保存前预算预判 |
| 巡览能力 | 无（滚动代替） | 自动巡览（打开/采集/切帖/末页停止） |
| 调试能力 | 无 | Debug 模式 + 导出诊断 JSON |
